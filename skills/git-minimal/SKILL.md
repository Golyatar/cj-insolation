# Git по минимуму

Предпочтение пользователя: короткий коммит и загрузка, без лишнего оформления.

- Проверить краткий status, текущую ветку, remote и сводку изменений. Читать только нужные участки diff; не выводить целые файлы, историю или повторяющиеся логи.
- Отправлять только изменения, относящиеся к запросу. Не включать отчёты, CSV, модели, секреты, локальные настройки и случайные файлы. Для добавления предпочитать явные пути.
- Использовать уже выполненные проверки. Запускать необходимые проверки, если новые изменения или ошибки требуют их; не повторять успешно пройденное без причины.
- Если есть изменения — один короткий содержательный коммит. Если нужные коммиты уже созданы — только push. Сохранять существующие ветку, remote и автора.
- Просьба пользователя отправить работу разрешает соответствующие commit/push. Создание скилла или вопрос о Git сами по себе не разрешают отправку кода.
- Не создавать репозиторий, ветку, PR, тег, релиз, архивы или документацию без отдельного запроса. Не делать force push, reset или amend по умолчанию.
- После ошибки обычного push не повторять одно и то же многократно. Если в этом проекте уже есть проверенный API-способ отправки в тот же репозиторий с сохранением SHA, можно использовать его один раз в рамках разрешённой загрузки. При ошибке или несовпадении SHA остановиться и сообщить причину. Не менять права доступа или настройки прокси ради обхода сбоя.
- Проверить успех один раз. Финальный ответ: коротко результат, ветка/коммит и ссылка; при неуспехе ясно сказать, что не отправлено.
