# Инструменты разработки CJ для SketchUp

Мост даёт Codex доступ к нескольким запущенным экземплярам SketchUp через MCP. Он может читать структуру моделей и выполнять перечисленные команды изменения без захвата окна.

## Запуск

MCP `sketchup-cj` уже настроен в Codex. Для автоматического запуска Ruby-моста в каждой версии SketchUp установи загрузчик один раз:

```powershell
.\tooling\install_bridge.ps1 -SketchUpVersion 2022
```

Перезапусти SketchUp. У моста собственный загрузчик `cj_bridge_loader.rb`, панель **CJ Bridge** и меню `Extensions → CJ Bridge`. Кнопка **«CJ Bridge: подключить»** открывает подключение к текущему экземпляру. Плагин инсоляции работает отдельно на панели **CJ Инсоляция**, не загружает мост и не содержит его в RBZ.

Затем Codex вызывает `sketchup_list_instances`, выбирает `instance_id` нужного файла и передаёт его следующим командам. Подробный перечень инструментов и проверки — в [MCP README](mcp/README.md).

Кнопка с цепочкой на отдельной панели `CJ Bridge` открывает окно подключения. В нём видны состояние моста, модель и PID; доступны подключение, перезапуск, отключение, обновление исходников плагина и его проверки. Готовность моста означает готовность принимать команды; подключение MCP в Codex настраивается отдельно. Окно обновляет состояние автоматически.

Если загрузчик не установлен, мост можно запустить вручную в Ruby Console:

```ruby
Kernel.load('C:/Users/Golyatin.av/Documents/ChatGPT/Skethcup инсоляция/tooling/sketchup_bridge.rb')
```

## Что доступно

Инспекция модели, поиск объектов, чтение/смена выделения, проверка пересечения луча, создание линии или грани, изменение имени/видимости/тега/материала, перемещение, удаление, сохранение, перезагрузка CJ и диагностические проверки. Изменения геометрии можно отменить через Undo. Произвольное выполнение Ruby или команд Windows не открыто.

Вызовы SketchUp Ruby API исполняются внутри главного потока соответствующего SketchUp. Окно не нужно активировать специально; модальное окно или долгий Ruby-скрипт могут задержать очередь.

## Тестирование

Протокол, схемы команд и выбор между несколькими моделями:

```powershell
python .\tooling\mcp\test_server.py
```

Проверки в запущенном SketchUp (нужен свободный тестовый файл; геометрическая проверка создаёт временную стену и откатывает её):

```powershell
python .\tooling\mcp\test_server.py --live
```

Результаты сохраняются в `reports/mcp_check.json`. Для повторяемых тестов текущего CJ смотри [VALIDATION.md](VALIDATION.md) и [ROADMAP.md](ROADMAP.md).

## Устройство

```text
Codex → MCP по STDIO → очередь файлов выбранного instance_id
                              ↓
                    Ruby-таймер этого SketchUp
                              ↓
                     SketchUp Ruby API
```

У каждого экземпляра свой UUID-сеанс и папка очереди в `tooling/runtime/instances`. Команды проверяют heartbeat и идентификатор сеанса. Мост не поднимает сетевой порт. Очередь является локальной доверенной границей: не давай доступ к папке проекта незнакомым процессам.

## Ограничения

Это широкое управление моделью через доступные публичные методы Ruby API, а не автоматизация любого окна. Работа с диалогами сторонних расширений, неизвестными инструментами и произвольным вводом в UI остаётся за пределами API моста. Снимки окна пригодятся для визуальной оценки и поведения мыши, если пользователь отдельно попросит.

Официальные источники: [SketchUp Ruby API](https://ruby.sketchup.com/) и [MCP tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).
