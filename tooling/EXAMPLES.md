# Работа по примерам SketchUp

## Доступные методы

- `sketchup_capture_model`: точные координаты в миллиметрах, границы, контуры граней с отверстиями, вложенность, матрицы преобразования, материалы и ID. Полные данные сохраняются в JSON. По умолчанию ответ содержит путь и верхний уровень; детали читаются из файла по необходимости.
- `sketchup_capture_view`: PNG текущего вида через Ruby API без изменения камеры. Это изображение модели, а не управление мышью или захват рабочего стола.
- `sketchup_export_model`: полный экспорт DAE/OBJ для внешних программ; доступность формата зависит от SketchUp. Не сохраняет исходный SKP.
- Существующие команды: выделение, поиск объектов, raycast, создание линий/граней, перемещение, материалы, удаление с Undo, проверки плагина.
- `compare_examples.py`: сравнение позиций вершин в мировой системе координат и количества элементов с допуском. Не доказывает равенство топологии, материалов или правил построения.

## Как показать пример

1. В отдельной модели подготовить исходную геометрию и ожидаемый результат, желательно в именованных группах.
2. Описать условие: например, по какой стороне линии строить, какие размеры задаются параметрами и что меняется при другой длине.
3. Выделить исходные объекты и снять JSON; затем отдельно выделить ожидаемый результат и снять второй JSON. Вложенное выделение учитывает текущий контекст редактирования.
4. Геометрия и PNG используются совместно. Из одного примера нельзя однозначно вывести все условия; спорные условия уточняются.
5. Реализация проверяется на других исходных данных в тестовой модели. Сравнение снимков служит одной из проверок.

## Один вызов для чтения

Из папки проекта установленным Python:

```powershell
python tooling/mcp/read_model.py --view
python tooling/mcp/read_model.py --selection
python tooling/compare_examples.py expected.json actual.json --tolerance-mm 0.1
```

Если доступно несколько экземпляров, требуется `--instance UUID` — автоматического выбора первого окна нет. `--reload` в read_model.py предназначен для перезагрузки доверенного исходника плагина при разработке.

Снимки сохраняются в `tooling/runtime/instances/<UUID>/`; это временные файлы, которые не входят в Git. Нужные учебные примеры следует скопировать в отдельную папку проекта вместе с описанием условия.

## Выбор файла и ограничения

Каждая команда может принимать `expected_model_token`, полученный из status. Скрипт чтения всегда передаёт его: если активный документ сменился, запрос отклоняется. Это защита от работы с другим файлом, а не управление произвольным неактивным документом внутри одного процесса. Для фоновой работы используйте отдельный экземпляр SketchUp.

Снимки ограничены числом элементов и глубиной. При `truncated: true` нужно уменьшить выделение либо увеличить лимит. Повторные экземпляры компонентов учитываются отдельно, с собственными путями и мировыми координатами. Снимки больших моделей не нужно целиком отправлять в чат.

Обновлённый сервер предоставляет 18 MCP-команд. Уже запущенное соединение Codex может продолжать показывать старую версию; после перезапуска подключения sketchup-cj список обновится. read_model.py обращается к текущему исходнику сервера независимо от старого процесса Codex.
